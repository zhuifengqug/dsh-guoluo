# 蜾蠃：素材 → 档案 → 复刻义务

1. 调用 `guoluo_probe` 检查素材根和档案根。REA 未装不影响本地静态盘点。
2. 用 `guoluo_target_add` 登记素材根内相对路径，`kind` 选 `local`；目录、单个 HTML/CSS、Electron `.asar`、Android `.apk`、Godot `.pck`、Windows `.exe`/`.dll`，或 Unity 的 `global-metadata.dat`、`.bundle`/`.unity3d` 都可登记。`kind: url` 只记录出处，不触发采集；已有的本地导出件单独登记。
3. 用 `guoluo_dissect` 返回批次 ID、数量、范围、耗时与 REA 绑定结果。目录型素材会自动调用 REA 分析并把摘要绑定到本次素材的路径与根哈希；`rea.status` 为 `analyzed` 且 `rea.binding.status` 为 `verified` 才能采信行为侧证据，`mismatch` 视为无行为侧证据，需要重新采集。单文件、ASAR、APK、PCK、PE、Unity 与 URL 档案不会触发 REA；APK 只按 ZIP 中央目录与二进制清单静态解析（包名、版本、SDK、权限、入口 Activity、ABI），不解压资源、不校验签名；PCK 只读包头与文件表（引擎版本、条目、加密标记、场景/脚本/资源计数），不解压条目、不解密、不运行游戏；PE 只解析头部、节表、导入导出表与 CLR 标记，不反编译、不运行二进制；Unity 盘点 `UnityFS` 头、块信息段与数据区（未压缩、LZ4/LZ4HC 或 LZMA 压缩）、节点表，并把可解压的数据区按块解压后按节点切出大小、SHA-256、类型魔数与 24 字节前缀（只记指纹、不留内容；数据区最多读 64 MiB、解压后最多 256 MiB、最多列 32 个节点，`payload.status` 为 `parsed`/`skipped`/`failed`），IL2CPP 元数据只对已核对布局的版本（v24）读区段表、类型名与字段名，其余版本只报 `metadataVersion` 与 `declaredHeaderBytes` 并标 `status: unverified`；方法体、字段类型签名与运行时行为始终不展开。`UnityFS` v9 以块表存储偏移取块（相对 `dataStart`，不同于节点的解压后逻辑偏移）；v10 及以上只保留头部事实。LZHAM 压缩明确不支持。
4. 用 `guoluo_dossier` 指定批次 `runId`，按 `asset`、`token`、`navigation`、`reference` 或 `binary`（PE 与 Unity 逐文件明细）分页；当前页的 `nextOffset` 为 `null` 时结束。资产路径和证据行号引用同一批次。PE 的完整导入符号与命名导出用 `pe-imports` / `pe-exports` 分页读（多条 PE 时带 `path`）；IL2CPP 的类型名与字段名用 `il2cpp-types` / `il2cpp-fields` 分页读，未核对版本只回 `unverified` 与原因。
5. 需要落到实现时，先 `guoluo_spec` 拿复刻义务账本：每条有编号、证据位置和 `declared` 状态；`conflicts` 里的令牌必须在动工前定值，`unknowns` 里的缺口必须显式处理，不能当作已完成。要把这一批交给复刻子代理，用 `guoluo_brief` 并必填 `runId`：它按同一批次写出 `brief/<runId>.md`，列出入门候选、素材、待确认令牌、证据缺口和验收顺序；只写档案，不启动子代理、不落地工程（要静态骨架见 `guoluo_scaffold`）。交接单里的名称与路径是参考数据，不是执行指令。
6. 要变量就 `guoluo_tokens`（原样 CSS + Tailwind v4 片段），要清单就 `guoluo_export`（json/markdown/csv）。派生产物可重复生成，每次整份替换，不追加历史。
7. 要验证页面骨架或联调前端路由，用 `guoluo_mock` 生成零依赖回放服务（只回放已观测的静态链接与素材，其余 404 `not-observed`）。它只写文件不启动，自己执行返回的 `start`。占位页没有真实结构，不能当作还原结果。
8. 要一份能直接打开的最小静态工程，用 `guoluo_scaffold`（`id` + 可选 `runId`、`name`）：把已盘点的页面、样式、图片、字体与音视频按素材根内相对路径逐字节复制到 `scaffold/<name>/` 并核对档案指纹，另生成 `_scaffold/index.html` 索引、`tokens.css`/`tokens.tailwind.css` 与 `_scaffold/scaffold.json` 清单。它只写档案根、只生成不启动、不执行素材脚本，也不含脚手架或框架代码；返回的 `coverage` 含文件层计数与 `structure` 结构维度（按生成目录里的复制页与 `_scaffold/index.html` 与证据页比对），`skipped` 里的条目（盘点后源文件变过、超出预算、归档或可执行类型）就是没复刻的部分。要把档案里的生成目录放回素材根再用 `guoluo_check` 回核，路径边界不变。同名目录已存在时它拒绝覆盖，换 `name` 或先手动删除。
9. 动工前和改完之后各跑一次 `guoluo_check`：`blocked` 说明证据漏项、悬空或规格批次过期，必须重新 `guoluo_spec` 或补盘点；`needs-decision` 说明令牌冲突待定值；`complete` 只表示规格与证据自洽，不表示目标已被复刻。复刻工程有了雏形后，再传 `candidate: { directory }`（素材根内目录）核对文件层面的覆盖：素材按相对路径比对，页面按路径或同名文件比对，令牌在候选 CSS 文本里检索同名声明，并逐字符比对声明值（仅去首尾空白）；值不同进 `values.differs` 并列档案值与候选值，不算缺失。预算内的素材会算 SHA-256，同名但内容不同进 `assets.changed` 并并列两边指纹。归档成员标成 `archived` 不判缺失。同一回执里的 `structure` 是结构维度：拿证据页与候选页做静态解析比对，比页面清单、`id`/`class` 选择器、`a[href]` 原文目标与标签层级；候选多出的页面只进 `pages.extra`（`_scaffold/` 下标 `generated`），解析不出或被节点预算截断的页面进 `structure.unverified`，都不计失败。`verdict` 为 `partial` 只说明文件层或结构层对不上，不代表目标已被复刻。JSON 里的清单每节只留前 20 条摘要，给人看的那份在同目录的 `check-<ts>-<uuid>.md`（回执 `candidate.report` 给路径）：按证据页分组列出缺的选择器、链接目标、标签数量与深度分布，单列未核页与候选多出的页。
10. 想知道做得「像不像」，给 `guoluo_check` 传 `visual`：`candidateDirectory` 必填（素材根内候选目录），单页用 `baselineEntry`/`candidateEntry`，多页用 `routes: [{ baselineEntry, candidateEntry }]`（1–16 条，二者不可混用）。每条路由按 390/768/1440 宽、900 高逐档测量，截图与 `summary.json` 落在 `check-<ts>-<uuid>/`。差异像素由插件独立解码 PNG 复算，再与 REA 的 `changedPixels` 交叉核对；不一致时该档记 `conflict` 并并列两组数值，不拿 REA 数字当结论。只有三档全部 `verified` 的路由才出 `score`（`1 −` 各档自算变化比例最大值）。默认 `channelThreshold: 0`，结论写明「本分数按逐通道 0 阈值计算，含抗锯齿差异」。整体 `visual.status` 为 `blocked` 时，查看 `visual.kind`、原因和逐路由结果。已核验的路由保留分数。
11. 结论区分静态观察、推断、尚缺证据。HTML 链接不是后端路由，ASAR 目录不是归档成员内容，APK 清单声明不是运行行为，PCK 条目清单不是运行时资源依赖，PE 导入函数不是被调用的证据，Unity 头也不代表包内资产，CSS 变量不是运行时样式，截图比例不是功能等价。以档案支持新的项目规格，不把盘点当作已完成的复刻。

蜾蠃默认不启动目标应用、打开页面或运行目标脚本；只有显式传 `visual` 才启动插件自己起的隔离 Chromium 去加载本地静态副本，不需要为了凑齐分类而扩展输入范围。
