# 蜾蠃 v0.8.1

## 复审修复

- Godot 4.7.2 生成的真包把零字节文件放在文件表起点。PCK 读取器现在接受这个边界，继续校验非空条目与文件表是否重叠。目录超预算时保留包头和声明条目数，覆盖标记为截断。
- UnityFS v7 的范围检查计入 16 字节对齐，同时覆盖 UnityPy 识别的 2019.4.15 起的 v6 对齐变体。UnityPy 生成并独立回读的 v7 测试包采用尾置 LZ4 块信息，压缩前后长度分别为 71 和 41 字节。
- Unity 盘点单列读头预算跳过数，逐文件明细保留读取失败状态。mock 统一用「Unity 候选素材未纳入回放」描述未回放条目。
- v0.8.0 后的分页修复约束每页证据行的序列化字节，并完整返回单条记录。APK 清单状态与目录扫描截断进入规格。

## 验证

- `npm run check` 在设置 `GUOLUO_TEST_REA` 后 57 项全部通过，包含两项真实 REA 视觉用例。打包清单为 22 个文件。
- 从最终 tarball 离线安装并在隔离 DSH 0.2.2-rc.5 profile 冷启动。11 个工具、技能与命令注册通过，设置热更新通过。REA 摘要绑定路径由假 REA 夹具验证。宿主读出 PCK 的两个条目及 UnityFS 尾置 LZ4 长度 41。
- [安装包](deliverables/zhuifengqug-dsh-guoluo-0.8.1.tgz) 为 48094 字节，SHA-256 为 `972C957A0DA4EB2510214B75A67C6932567540A7ADF1652DF98123A8756B68E6`。

## 剩余范围与待决

- 加密 PCK 条目仅检查起点和声明大小，实际存储区间仍待验证。Unity 的读取结束检查使用同一个已打开句柄，素材路径在读完后是否仍指向同一文件尚未验证。Unity 证据范围仍为头部。
- [复刻交接与 craft-anything 边界](../2026-11-21-v0.8/craft-anything-boundary.md) 记录了批次固定、独立候选目录及验收入口。子代理复刻还需要在自制样例上实跑一次。
- G 的待决项集中在视觉验收。是否覆盖多个路由，是否由插件独立计算像素差异，以及逐通道差异阈值的默认值。当前实现保持单入口、默认阈值 0 和 REA 计算口径。
